Fakta penting dari kode aktual:

1. **PrimeVue belum punya locale** (`main.js` hanya `theme`). Teks bawaan komponen (kalender, paginator, filter, "Yes/No", dsb.) masih Inggris. Perlu `app.use(PrimeVue, { locale })`.
2. **`formatters.js` mengunci Indonesia**: `MONTH_NAMES_ID`, sufiks `WIB`, `Intl.NumberFormat('id-ID')`. Harus ikut locale aktif.
3. **`index.html`** `lang="en"` (kini salah untuk bahasa bawaan `id`). Boleh diubah oleh A (hanya atribut `lang`).
4. **Pesan backend berbahasa Inggris** (169 literal `'message' => ...` di `laravel-api/app`), tidak ada `lang/`. Frontend menampilkan sebagian apa adanya, sehingga UI Indonesia bercampur Inggris.
5. **`referenceLabels.mjs` membaca `laravel-api/resources/reference-labels.json`** (17 domain, 243 entri; nilai Indonesia → English, mis. `Pendidik → Teacher`). Peta ini sudah berarah ID→EN dan milik area `laravel-api/**`.
6. **Demo Sakai tidak dirutekan**: `views/uikit/**`, `Documentation.vue`, `Crud.vue`, `Landing.vue` tidak diimpor `router/index.js` (hanya saling mengimpor). `service/*` hanya dipakai oleh berkas demo itu.

## 2. Arsitektur

- Pustaka: `vue-i18n` (Composition API, `legacy: false`), versi stabil terbaru yang kompatibel Vue `^3.4`; **versi diverifikasi saat instalasi**. Satu-satunya dependensi baru (diizinkan bagian 3.9).
- Lokasi: `vue-app/src/i18n/`
  - `index.js` — `createI18n`, locale awal, fallback `id`
  - `locales/id/*.json`, `locales/en/*.json` — satu berkas per namespace
  - `useLocale.js` — komposabel: `locale`, `setLocale`, sinkron `localStorage`, `document.documentElement.lang`
  - `primevue.js` — objek locale PrimeVue `id` dan `en`
- Bahasa bawaan `id`; fallback `id`. Preferensi di `localStorage` (kunci `app.locale`), **tanpa kolom DB, tanpa migration, tanpa perubahan kontrak API**.
- Pindah bahasa **tanpa reload**: `locale` reaktif; PrimeVue `config.locale` diperbarui via `usePrimeVue()` saat `setLocale`.
- Sumber string non-templat (konstanta modul, `ref([...])` menu, `breadcrumb` rute, opsi dropdown) diubah menjadi **kunci**, lalu diterjemahkan saat render (`computed`/`t()`), bukan saat modul dimuat, agar reaktif terhadap pergantian bahasa.
- Tanggal/angka: `formatters.js` memakai `Intl.DateTimeFormat`/`NumberFormat` dengan locale aktif (`id-ID` / `en-GB` untuk DD/MM/YYYY), zona **WIB tetap** (`Asia/Jakarta`); sufiks zona waktu tetap "WIB" di kedua bahasa. Perilaku default `id` dipertahankan identik (uji regresi format).
- Nama diri tidak diterjemahkan: "Sekolario", singkatan resmi (NISN, NIK, NIP, NUPTK, PTK, Dapodik, WIB), nama peran kanonikal (`admin-sistem`, dst.), data dari DB (nama siswa/pegawai/sekolah).

## 5. Pesan dari API (keputusan diperlukan)

Pesan backend Inggris dan sebagian ditampilkan ke operator. Opsi, **tanpa mengubah kontrak API**:

- **P1 (disarankan)**: frontend memetakan dari **pola pesan/kode HTTP** ke kunci `errors.api.*`; pesan tak dikenal ditampilkan generik (`errors.api.unknown`) dan pesan asli hanya di konsol dev. Sebagian besar toast sukses/gagal sudah ditulis frontend, jadi cakupan bergantung pada audit 131 titik pakai.
- **P2**: biarkan pesan backend apa adanya (tetap Inggris di kedua bahasa). Paling murah, tetapi tidak memenuhi "tidak ada teks campuran".
- **P3**: backend menerjemahkan (`lang/`, header `Accept-Language`). Menyentuh `laravel-api/**` dan kontrak; **di luar scope** kecuali disetujui.

## 6. `reference-labels.json`

Berkas milik `laravel-api/resources/`, sudah berisi pasangan ID→EN untuk 243 nilai master. Rencana: `referenceLabel()` memilih nama tampilan menurut locale (`id` = nilai asli DB; `en` = terjemahan di JSON). Ini **tidak mengubah JSON** bila JSON tetap dibaca apa adanya; perubahan hanya di `referenceLabels.mjs` (milik A). Bila ada entri yang perlu ditambah di JSON → ajukan lewat `REQUESTS.md`.
